# План 3 — клиент

Лобби, комната, табло, победа. Всё поверх готового сервера и потока событий.

## Границы

Входит: вход гостем, лобби, создание и вход в комнату, зал ожидания, табло, журнал раздач с правкой, экран победы, переподключение к потоку, тёмная тема.

Не входит: история и статистика — экраны `/history` уезжают в план 4 вместе со своими эндпоинтами `/api/me/games` и `/api/me/stats`. Раньше план 3 обещал экраны, которым не к чему подключаться.

## Решения

| Развилка | Решение | Почему |
|---|---|---|
| Очки | Только положительные | Решение владельца. Ошибка исправляется правкой записи, а не минусом |
| Правка записи | Новый маршрут `POST /api/entries/:id/replace` | Через «отменить + дописать» двумя запросами отмена победной записи возвращает игру в active, и у всех мигает экран победы. Одна транзакция — одно согласованное состояние |
| Состояние | Стор заменяет снимком из каждого кадра | Сервер уже шлёт `state` с каждым событием; собирать состояние из дельт клиенту не нужно |
| Переподключение | Своё, с новым билетом | Билет одноразовый, нативное переподключение `EventSource` упирается в 401 и глохнет навсегда |
| Первый вход | Гейт `/hello` с возвратом по `next` | Ссылка-приглашение должна работать у человека без аккаунта: `/room/ABC123` → ник → обратно в комнату |
| Тесты | Vitest, Vue Test Utils, happy-dom | Стор и сборка экранов. На сервере тесты ручек поодиночке пропустили, что табло физически не рисуется, — на клиенте проверяем именно отрисовку |

Лимит очков принадлежит игре: задаётся при старте, последнее значение подставляется по умолчанию.

## Устройство

```
client/src/
├── api.ts              # обёртка fetch: Bearer, единая форма ошибки
├── realtime.ts         # билет, EventSource, переподключение с отступом
├── router.ts           # /hello, /, /room/:code
├── stores/
│   ├── session.ts      # токен, свой профиль, восстановление по /me
│   ├── lobby.ts        # список комнат
│   └── room.ts         # RoomState, статус связи, действия
├── views/
│   ├── HelloView.vue   # ник гостя
│   ├── LobbyView.vue   # список комнат и создание
│   └── RoomView.vue    # разводит зал ожидания, табло и победу
└── components/
    ├── WaitingRoom.vue    # состав, выбор лимита, «Старт» у хоста
    ├── GameScreen.vue     # табло, счёт из стора
    ├── PlayerCard.vue     # + «онлайн», «это вы», хост
    ├── EntriesLog.vue     # раздачи, отмена и правка
    ├── VictoryScreen.vue  # + «Играть ещё» у хоста
    └── ConnectionBanner.vue
```

Тёмная тема и её ключ в `localStorage` переносятся как есть.

## Шаги

1. Сервер: маршрут `replace` с тестами.
2. Оснастка клиента: vitest, test-utils, happy-dom, pinia, vue-router.
3. `api.ts` и стор сессии; гейт `/hello` с возвратом по `next`.
4. `realtime.ts`: билет, поток, переподключение с отступом.
5. Стор комнаты: применение кадров, статус связи.
6. Лобби: список, создание, вход по паролю.
7. Зал ожидания и старт игры.
8. Табло и карточка игрока.
9. Журнал раздач: отмена и правка.
10. Экран победы и «Играть ещё».
11. Сборка старого `App.vue` под роутер, снос `types.ts`.
12. Проверка в браузере на двух вкладках.

## Проверка

`pnpm --filter client test`, `pnpm --filter server test`, `pnpm typecheck` перед коммитом. Шаг 12 — руками: две вкладки, запись очков в одной видна в другой, обрыв сети и возврат.
